# 数据管理规范

HoloDub 的数据按“价值等级”管理：等级决定存放位置、能否删除和保留多久。本文件同时记录现状、已做的清理和迁移进度。

## 1. 数据等级

| 等级 | 内容 | 规则 |
|---|---|---|
| L0 原始素材 | 原片、参考音色样本、人工确认的译文 | 只读、单份、记录 SHA-256 与来源，永不自动删除 |
| L1 交付物 | 已发布/待发布的成片、字幕 | 按 `课程/讲次/版本` 存放，附 `provenance.json`（原片、任务/剧集 ID、代码提交、模型版本、配置），不可覆盖 |
| L2 高成本产物 | 段落配音、ASR 词级结果、LLM 译文 | 重新生成要花 GPU 时间或 LLM 费用；活跃项目保留，交付稳定后可归档 |
| L3 可重算缓存 | 章节切片、分离音轨、重采样文件 | 可随时删除，按需重新生成 |
| L4 实验 | LoRA 训练、探针、对照实验 | 必须挂在一个实验编号下，结束后归档或删除 |
| 模型 | 官方权重 | 按“名称@官方版本”只存一份 |
| 临时 | 调试输出、草稿 | 7 天有效期 |

## 2. 目标目录结构

`F:/HoloDubData` 是唯一的数据根目录，挂载为容器内的 `/data`（`DATA_ROOT`）。代码仓库内不再存放数据。

```text
F:/HoloDubData/
  catalog/catalog.sqlite                ← 数据目录：每个文件一条记录（路径、大小、SHA-256、等级、归属、来源）
  sources/mit-6.824-2020/lec-01.mp4     ← L0，规范命名，只读
  sources/test-clips/                   ← L0，从原片截取的测试片段
  assets/voices/                        ← L0，参考音色
  deliverables/mit-6.824-2020/lec-01/v1/final.mp4 + provenance.json   ← L1
  jobs/  episodes/                      ← L2/L3 运行数据，保持现有相对路径不变
  models/hf-cache/  models/torch-cache/ ← 模型，单份
  experiments/<实验编号>/                ← L4
  archive/                              ← 冷存档
  scratch/                              ← 临时
```

`jobs/` 与 `episodes/` 保留在根下，数据库中段落音频等上万条路径无需改写。同一块 F 盘上的移动只是改目录名，不复制数据。
